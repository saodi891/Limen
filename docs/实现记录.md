# Limen 实现记录

## 2026-07-25 初始工程脚手架

已实现：

- Forge 1.20.1 Gradle 工程骨架。
- Mod ID：`limen`。
- Java 包名暂定：`com.moonlightc.limen`。
- GeckoLib 依赖接入，用于复杂实体动画。
- 基础配置系统：common/client。
- 基础注册系统：物品、实体、创造模式标签页。
- 正式第一只实体：`pama_detector`。
- 正式第一只实体刷怪蛋：`pama_detector_spawn_egg`。
- 技术样板 GeckoLib 模型与动画 JSON 占位。
- 中英文语言文件。
- 实体 loot table 占位。
- Gradle Wrapper：`gradlew`、`gradlew.bat`、`gradle/wrapper/gradle-wrapper.jar`、`gradle/wrapper/gradle-wrapper.properties`。
- 项目级 Java 配置：`gradle.properties` 已设置 `org.gradle.java.home=C:/Program Files/Java/jdk-17`。
- Windows Wrapper：`gradlew.bat` 会优先使用 `C:\Program Files\Java\jdk-17`。
- 辅助脚本：`use-java17.bat` 与 `use-java17.ps1` 可将当前终端临时切换到 Java 17。

构建验证：

- 已下载临时 Gradle 8.8 到 `.gradle-local/` 并尝试执行 `gradle build`。
- 当前环境没有全局 Gradle，因此使用临时 Gradle 进行验证。
- 构建未进入 Java 编译阶段，阻塞在当前网络/代理对 Mojang 依赖仓库的 HTTPS/HEAD 请求处理上。
- 先后遇到 Java 证书链问题；导入仓库证书后继续推进，但最终阻塞于 `libraries.minecraft.net` 对多个 Mojang jar 的 HEAD 请求返回 `421 Misdirected Request`。
- 项目正式配置中未保留本机 truststore 路径；`.gradle-local/` 已加入 `.gitignore`。

注意：

- `pama_detector` 是第一阶段 Boss 红石计算机 PAMA 的基础单位。
- 用户提出的概念命名为 `PAMA_detector`；代码和资源 ID 使用 Minecraft 兼容的小写形式 `pama_detector`。
- `pama_detector` 初版具备无重力悬浮、飞行导航、空闲缓慢漂浮、锁定玩家、对称顺时针环绕和周期性施加原版发光效果。
- `pama_detector` 默认索敌范围为 16 格，参考骷髅级别索敌距离；范围、空闲速度、锁定速度、环绕半径、发光冷却和发光时长已配置化。
- 新增实体类型标签 `limen:redstone_machines`，当前包含 `limen:pama_detector`。
- 新增 API 标签常量 `LimenEntityTypeTags.REDSTONE_MACHINES`，供后续仇恨过滤、PAMA 造物联动和附魔增伤逻辑复用。
- `pama_detector` 的受击仇恨目标会跳过同属 `limen:redstone_machines` 的实体。
- 贴图文件 `textures/entity/pama_detector.png` 仍需由正式资源替换或补充占位图。
- 公开发布前需要把 `mods.toml` 的 issue tracker、license、authors 等元数据改成正式内容。

## 2026-07-26 构建环境与探机编译修复

已确认：

- `gradlew.bat --version` 正常启动，Gradle 版本为 8.8。
- Gradle 当前使用 JDK 17：`C:\Program Files\Java\jdk-17`，实际 JVM 为 17.0.12。
- 退出 Steamcommunity302/相关 HTTPS 代理后，ForgeGradle 可以继续下载和处理 Minecraft/Forge/GeckoLib 依赖。
- 完整执行 `.\gradlew.bat build --stacktrace --no-daemon` 已成功。
- 构建产物：`build/libs/limen-0.1.0.jar`。

修复内容：

- `PamaDetectorEntity` 原先尝试继承/复用 `HurtByTargetGoal`，但 Forge 1.20.1 中该目标要求 `PathfinderMob`，而 `FlyingMob` 不满足该类型约束。
- 已改为自定义轻量 `RedstoneMachineHurtByTargetGoal extends Goal`：
  - 当探机被非 `limen:redstone_machines` 实体攻击时，将攻击者记录为目标。
  - 当攻击者属于 `limen:redstone_machines` 时不产生仇恨。
  - 保留“红石器械之间不会互相仇恨”的设计目标。

仍存在但不阻塞：

- `ModLoadingContext.get()`、`FMLJavaModLoadingContext.get()`、`new ResourceLocation(namespace, path)` 在当前 Forge/MC 映射下会给出 removal/deprecated 警告。
- 这些警告不影响当前 Forge 1.20.1 构建，后续可在整理脚手架时替换为新版推荐 API。

## 2026-07-26 zombie_chipped 与红石器械共性机制

已实现：

- 新增红石器械共性事件：
  - 所有 `limen:redstone_machines` 实体不会因攻击被击退。
  - 所有 `limen:redstone_machines` 实体会对跟随范围内处于发光状态的玩家产生即时仇恨。
- 新增第二个生物 `zombie_chipped`（受控制僵尸）：
  - 归类为 `limen:redstone_machines`。
  - 不会在阳光下燃烧。
  - 默认索敌范围为普通僵尸常见 35 格的一半，即 17.5 格，并已配置化。
  - 不生成装备，不保留首领/破门/增援等特殊强化效果。
  - 头部入水时会转化为普通僵尸，并按配置概率额外掉落 0-1 个 `damaged_chip`。
  - 死亡时除僵尸原版掉落外，额外按配置概率掉落 0-1 个 `damaged_chip`。
- 新增物品：
  - `damaged_chip`
  - `zombie_chipped_spawn_egg`

构建验证：

- `.\gradlew.bat compileJava --stacktrace --no-daemon` 通过。
- `.\gradlew.bat build --stacktrace --no-daemon` 通过。
